# Adaptive Motion Graphics Production

Produce a professional, engaging, informative motion graphics video from the user's supplied SRT, video, voiceover audio, script, or any combination. The visual language, animation style, scene composition, color palette, typography, iconography, and storytelling pattern **must be derived from the actual subject matter of the content**, not from any default template.

Do not force programming imagery (IDE windows, terminals, code typewriters, syntax highlighting, developer dark themes, `{ }` watermarks) onto content that is not programming-related. Programming aesthetics appear only when the SRT/script explicitly concerns coding, software engineering, scripts, APIs, or developer tooling.

Use the installed Remotion Motion Graphics Skill to write the source code, render still frames of key scenes for visual validation, and deliver the project and video according to the designated output mode.

No production guideline guarantees avoidance of YouTube, Facebook, or any other platform's monetization decisions, copyright claims, or strikes.

## Inputs and scope

Any one of the following inputs is sufficient; all are not required:

- Voiceover SRT file.
- Original or reference video (MP4, MOV, WebM, or any supported format).
- Voiceover audio (MP3, WAV, M4A, or any supported format).
- Written script, article, document, or notes.
- Combinations of the above.
- Optional: user avatar, personal logo, brand assets, custom fonts, reference images, licensed images/footage, previous Remotion projects, specific resolution/color scheme, licensed SFX, music, subtitle preference, platform target.

**Input priority:** The file the user explicitly identifies as the Source of Truth takes precedence. Otherwise, use the SRT for speech timing and transcript, the video for visual reference, the audio for duration and sync, and the script for narrative structure. If sources conflict, report it rather than silently correcting.

If the user has already supplied information, do not ask again. If a file is uploaded, inspect it before asking speculative questions. Do not force the user to supply each asset individually—first search approved sources independently.

## Automatic initial inspection

On receiving files, automatically:

1. Verify file name, type, size, and readability.
2. For SRT: extract cues, timestamps, language, first/last cue, total duration, word count, speaking pace.
3. For video: analyse resolution, aspect ratio, frame rate, duration, audio track, scene changes, representative frames.
4. For audio: verify duration, sample rate/channel, audio-video sync.
5. If no SRT but speech exists, use available speech-to-text. If unavailable, state this clearly and request SRT/transcript. Do not fabricate a transcript.
6. For on-screen text and images in video, use OCR/frame inspection if available. Note what could not be verified.
7. Create a separate working copy; do not modify input files.

## Topic detection and content classification (mandatory first analytical step)

Before any visual decision is made, perform content classification by reading the entire SRT/script/transcript and identifying:

1. **Primary category** — pick one principal category:
   - Technology News / Product Announcement
   - Programming / Software Development / DevOps
   - AI / Machine Learning / LLM
   - Cybersecurity / Digital Safety
   - Business / Startup / Entrepreneurship
   - Finance / Economics / Investment / Crypto
   - Education / Tutorial / How-To (non-programming)
   - Science / Research / Space / Health
   - Documentary / History / Biography
   - Document-based / Report / Whitepaper summary
   - Product Review / Comparison
   - Marketing / Advertisement / Course Promo
   - Lifestyle / Food / Travel / Sports
   - News / Current Affairs / Politics
   - Religion / Culture / Society
   - Motivational / Self-help
   - Mixed / Other (specify)

2. **Secondary categories** — list any supporting topics in order of weight.

3. **Content attributes:**
   - Audience level (beginner, intermediate, expert, general public)
   - Tone (informative, dramatic, playful, serious, cinematic, corporate, intimate, urgent)
   - Narrative structure (problem→solution, chronological, listicle, comparison, case-study, breaking-news, explainer, story-driven)
   - Named entities (brands, products, people, locations, dates, numbers, prices, statistics)
   - Verifiable claims vs. opinion vs. illustrative examples
   - Visual opportunities per cue (what deserves imagery, data, a diagram, a map, a product shot, a headline card, a human face, a document, a chart, etc.)

4. **What the content is NOT about** — explicitly list visual metaphors to **avoid**. For example, a finance explainer must not use code editors; a food recipe must not use terminal windows; a cybersecurity news story must not use playful illustrations unless the tone warrants it.

Record this classification internally and use it as the constraint for every subsequent visual decision. If classification is genuinely ambiguous and would significantly change the output, ask one focused clarifying question.

## Visual direction selection (replaces generic "color scheme")

Based on the detected category and tone, propose **a Visual Direction** (not just colors) in a single concise message. A Visual Direction bundles:

1. **Theme Name** (e.g., "Editorial News Light", "Cinematic Documentary", "Soft Business Mint", "Dark Cybersecurity Alert", "AI Glass Futurism", "Warm Educational", "Clean Corporate", "Vibrant Marketing", "Minimal Scientific", "Developer Dark")
2. **Palette:** Background / Surface / Primary / Accent / Text / Muted (HEX)
3. **Typography family:** heading + body + numeric/mono + Bengali
4. **Visual motif:** background texture, grid, gradient, particles, cinematic blur, paper, light rays, 3D orbs, map, document, chart, etc.
5. **Mood descriptor** (one line)

Provide **4–6 directions** tailored to the detected category, with 1–2 recommended. Include at least one light and one dark variant. Example family mappings (adapt per project, do not use blindly):

| Category | Suggested Direction Families |
| --- | --- |
| Tech News / Product | Editorial News Light, Dark Keynote, Glass Futurism |
| Programming | Developer Dark, Clean IDE, Terminal Minimal |
| AI / LLM | AI Glass Futurism, Neural Dark, Soft Gradient Science |
| Cybersecurity | Dark Alert Red, Forensic Blue, Terminal Noir |
| Business / Finance | Clean Corporate, Soft Business Mint, Executive Dark |
| Education | Warm Educational, Friendly Pastel, Chalkboard Modern |
| Science / Health | Minimal Scientific, Clean Medical, Observatory Dark |
| Documentary | Cinematic Documentary, Vintage Paper, Archive Sepia |

End with exactly: "Which one would you like? State a number, specify your preferred color/theme, or simply say "you choose.""

If the user says "You choose" or similar, pick the top recommendation and proceed without further confirmation.

## Additional context prompts (ask only what matters)

Ask only questions whose answer meaningfully changes the output. Skip anything the user already provided. Candidate prompts:

- Target platform (YouTube, Shorts, Reels, Facebook feed, LinkedIn, internal).
- Branding (logo, brand colors, brand font, watermark position).
- Music preference (none / soft background / cinematic / upbeat / user-provided).
- SFX intensity (none / minimal / moderate / rich).
- Avatar/presenter usage (none / corner / full-scene / per-scene).
- Pacing (slow explainer / standard / fast social).
- Language mix (Bengali-primary, English technical terms allowed, English-primary, mixed).
- Any factual constraints or must-include claims.

Batch these into a single short message when multiple are needed. Do not interrogate.

## Complete SRT / script analysis

Read the entire SRT or script before writing production code. Identify:

- Main subject and purpose per the classification above.
- Narrative arc: hook → context → body → climax → recap → CTA (or alternative structure).
- Voiceover tone, delivery style, emotional beats.
- Key statements, quotable lines, named entities, numbers, dates, prices, statistics.
- Which cues suit: imagery, infographic, chart, map, timeline, document, product shot, headline card, comparison, quote card, diagram, process flow, avatar.
- Which cues contain verifiable claims (flag for factual verification).
- First cue, last cue, total duration.
- Where visuals should enter 4–6 frames before voiceover begins.
- Where SFX serves comprehension vs. decoration.

SRT timing is the primary synchronisation source.

## Original creator identity (adaptive)

**Signature identity components** that persist across videos regardless of category:

- Personal logo / monogram placement.
- Brand color seed (adjusted into each Visual Direction).
- Bengali font family and headline treatment.
- Avatar visual treatment (if user has one).
- Optional short intro/outro stinger.

**Adaptive components** that change per category: scene templates, iconography, imagery style, color temperature, typography accents, SFX palette.

If no avatar is supplied, do not fabricate one. Do not imitate other creators' distinctive branding.

## Scene planning

Divide the video into scenes using SRT speech and timing. For each scene, internally determine: start/end frame, corresponding cue, purpose, visual concept, main element, layout, on-screen text, subtitle configuration, animation style, SFX, assets required, factual verification needs.

**Scene flow (default; adapt per narrative):** Hook → Context → Main Explanation → Evidence/Demonstration → Recap → CTA (if relevant).

**Scene diversity rules:**
- A one-minute video typically uses 3–5 distinct visual styles.
- Never reuse the same layout in two consecutive scenes.
- Each scene has at least one meaningful main visual element.
- Avatar is not required in every scene.
- Variety must not disrupt narrative continuity.
- Do not add animation purely for variety.

Create the plan and proceed; do not request separate approval.

## Animation and motion graphics toolkit

Every animation must support the message, but every key phrase must be visualized. Available techniques:

- Spring entrances, staggered reveals, coordinated exits.
- Mask reveals, shape morphs.
- Ken Burns, parallax, subtle camera push/pull.
- Animated gradients, particle fields, light rays, atmospheric bloom.
- 3D layered illusions (parallax depth, orbs, floating cards).
- Animated charts (bar grow, line draw, pie sweep, counter roll — only real numbers).
- Timeline sweeps, map route draws.
- Image transforms (reveal, zoom, cross-dissolve).
- Lower-third slide-ins, headline tickers.
- Progress indicators (segment bars, dot steps).
- Audio-reactive accents (subtle, if music is present).
- Callouts, pointers, highlight sweeps, underline reveals.

Vary animation style across the video while preserving identity. Keep motion smooth and deterministic.

## Subtitle system (fully customizable)

Subtitles are a first-class component with their own configuration object. Customizable properties:

- `enabled` (boolean)
- `preset` (`minimal` | `news` | `karaoke` | `cinematic` | `social` | `custom`)
- `font` (family, weight, size, letterSpacing)
- `colors` (text, highlight, background, outline, shadow)
- `position` (`bottom` | `lower-third` | `center` | `top`, with safe-margin values)
- `maxLineLength` (characters), `maxLines`
- `segmentation` (`word` | `phrase` | `sentence`)
- `activeWord` (`box` | `underline` | `color-shift` | `scale` | `none`)
- `emphasisWords` (per-cue list of words to highlight)
- `entrance` / `exit` animations
- `backgroundBox` (none | solid | translucent | pill)
- `padding`, `radius`, `shadow`
- `languageFonts` (per-language font map for mixed-language content)

**Preset defaults:**

| Preset | Font Weight | Background | Active Word | Position | Tone |
|---|---|---|---|---|---|
| Minimal Clean | Medium | none | subtle color-shift | bottom safe | neutral |
| News Caption | Semibold | translucent bar | color-shift | lower-third | broadcast |
| Karaoke Highlight | Bold | translucent | underline + box | lower-third | energetic |
| Cinematic Documentary | Medium | none | gentle fade | center-bottom | elegant |
| Social Pop | Extra-bold | pill/box | scale + color pop | center | high-energy |
| Custom | user-defined | user-defined | user-defined | user-defined | user-defined |

**Bengali rendering rules (always):**
- Never animate letter by letter.
- Segment by spaces (word units), preserving conjuncts, vowel signs, reph, hasanta.
- `letterSpacing: 0` for Bengali.
- Verify readability on mobile.
- Verify mixed Bengali+English line wrapping.
- Suggested Bengali fonts: Hind Siliguri, Noto Sans Bengali, Baloo Da 2, Tiro Bangla.

**Subtitle timing:**
- Honour SRT timestamps and original wording. Do not rewrite unless user asks.
- Word-level highlight timing: distribute cue duration across words proportionally to character count unless word-level timestamps exist.
- Never display so much text that readability breaks.

A render with clipped, misaligned, or broken Bengali subtitles is not complete.

## Language and content

- On-screen explanations default to Bengali.
- English technical terms, brand/product names, and numbers may remain in English.
- Do not display the full voiceover on screen — use keywords, phrases, visuals.
- Do not fabricate numbers, statistics, features, prices, or claims absent from the script.
- Do not present mockups as real UIs; label clearly as "Illustrative example" / "Sample" / "Demo" where confusion is possible (see reference images using "Illustrative example" / "ILLUSTRATIVE DEMO" / "SAMPLE" badges).

## Factual verification

For any mentioned feature, price, date, statistic, availability, event, or named entity, verify from reliable sources. If verification is impossible in the environment, mark the claim as unverified in the delivery note. Do not present unverified information as confirmed fact. Preserve a timestamp of verification where relevant.

## Timing and synchronisation

- SRT is the primary source. Base all timing on SRT.
- Scene start/end frames align with cue timing.
- Visuals may enter 4–6 frames before corresponding speech.
- Multiple elements in one cue: stagger within cue duration.
- Verify animation duration does not exceed cue length.
- Do not silently fix SRT/audio mismatches; note them in the delivery.

## Asset management and copyright

**Automated asset discovery priority:**
1. User-supplied assets.
2. Brand's official media/press kit.
3. Public-domain / CC0 / clearly licensed sources.
4. Trusted stock/illustration/icon libraries (verify terms).
5. If rights uncertain, create custom SVG / Remotion graphic / text treatment.

**Per-category asset bias:**
- News/Tech → press-kit product shots, official logos.
- Documentary/History → public-domain archival imagery.
- Science → public-domain diagrams, generated clean illustrations.
- Business/Finance → generated charts from stated numbers.
- Marketing/Promo → 3D orbs, gradients, generated hero graphics.
- Programming → official brand icons (Devicons, Simple Icons) when licensing allows.

**Rules:**
- Visibility online ≠ right to reuse. Verify license.
- Do not distort logos. If logo unavailable, use brand name as styled text.
- Do not bypass logins, paywalls, DRM, CAPTCHA.
- Preserve `ASSET_MANIFEST.md` with: `asset_id`, `file_path`, `asset_type`, `source_url`, `creator`, `license`, `attribution`, `downloaded_at`, `scene_usage`, `verification_status`.
- Mask personal data (names, phone numbers, balances, API keys, account IDs) in any extracted or demonstrated UI.

## Video file input — special workflow

When a video is supplied:

1. Determine purpose: Remake / Enhance / Repurpose / Reference / Extract.
2. Analyse metadata, scene changes, representative frames.
3. Capture a frame index with timecodes of important moments → `VIDEO_ANALYSIS.md`.
4. Identify on-screen text, products, people, brands.
5. Match frames to SRT cues; generate transcript if needed.
6. Record which parts are retained, recreated, or omitted.
7. Verify reuse rights before extracting frames. Prefer own diagrams/mockups when third-party license is uncertain.
8. For aspect ratio conversion, use subject-aware crop or background extend; never center-crop if it clips key subjects.

## SRT, transcript, and audio workflow

- Parse SRT reliably; log but do not silently fix malformed cues.
- Without transcript: use STT if available; flag uncertain terms; never claim perfect accuracy.
- Use a single conversion rule: `frame = round(seconds × fps)`.
- Produce `TIMING_REPORT.md` comparing last cue, audio duration, composition duration.

## Motion density rules (MANDATORY - these override any older "keep it minimal" rule)
1. New visual EVENT every 30-45 frames (1-1.5 s). Events: a word/number lands, an icon draws,
   a line draws, a counter runs, a mask reveals, a card flips, the camera pushes, a particle burst.
   Target: at least 8 events per 10 seconds. Never more than 60 frames with nothing new.
2. Scenes are 2-5 s. Split long SRT sentences into several scenes/beats by PHRASE, not by sentence.
3. BEAT SHEET FIRST: before writing code, write a table: time | phrase | visual event | technique.
   One row per 1-2 s of voiceover. Save it as BEAT_SHEET.md. Build from it.
4. Every key noun, number or verb in the voiceover gets its own visual (icon, kinetic word, counter, diagram).
5. Camera: every scene container does a slow push/pan (1.00 -> 1.06) and has 3 parallax layers.
6. Scene changes are HARD CUTS. No transition overlays (no whip, sweep, wipe, slide, flash, scale-through).
   Each scene animates its own content in and out only.
7. Technique inventory: use at least 8 different techniques per video from: kinetic typography,
   counter, line/path draw, mask reveal, parallax, shape morph, progress ring, particle burst,
   animated cursor/tap on a screenshot, scroll simulation, chart grow, orbit/radial diagram.
8. Screenshots: crop, zoom, add callouts and a moving cursor. If a screenshot is under 800 px wide
   and must be enlarged, say so and ask the user for a higher-resolution file.
9. Glow: one PRIMARY glow per frame, but secondary accents and particles are allowed.
10. Final check: count events per 10 s from the rendered frames and list the count in TIMING_REPORT.md.

## Cuts and sound (MANDATORY - overrides anything above)
1. Scene changes are HARD CUTS. Never create a Transition component, transition overlays, or a
   transition column in BEAT_SHEET.md.
2. Never use whoosh, swipe, riser or sweep sounds, anywhere. Allowed SFX: pop, click, tick, ding, alert
   (and keystroke for programming).
3. Place SFX only on content events (a number lands, a check appears, a line is typed),
   never on scene cuts.
